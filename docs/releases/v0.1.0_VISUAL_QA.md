# Alpine v0.1.0 — Release-Gate Visual QA (issue #12)

**Fecha de la auditoría:** 2026-08-24
**Commit auditado (tag `v0.1.0` / `main`):** `46a50932bda19048c66dd7da76a3cbf4a82a7c19`
**Commit de esta auditoría (correcciones de documentación, encima del tag):** `50ad2777fea3e5dcd4d456880e4bb2091cd972c0`
**Entorno:** contenedor de sesión remota, Python 3.11 (repo requiere ≥3.12; ver limitación abajo), Streamlit 1.56.0, `streamlit.testing.v1.AppTest` (renderizado headless real, sin navegador).

## Método

Se ejecutó `app.py` mediante `AppTest.from_file("app.py")`, seleccionando el
territorio **PN Sierra Nevada** (`selected_key="sn"`) en el radio de la barra
lateral y recorriendo mecánicamente:

- las 2 temporadas del observatorio alpino (`AlpineSeason.WINTER` / `SUMMER`),
- las 3 vistas de audiencia (`Técnica`, `Gestor`, `Auditoría científica`),
- las 4 capas de navegación declaradas en `src/ui/navigation.py`
  (`Decidir`, `Diagnosticar`, `Evidenciar`, `Gobernar`), confirmando que
  todos sus módulos (`panorama, urgent_actions, budget, socioeconomic`,
  `spatial, alpine, assets, pressure, forecast`,
  `satellite, confidence, provenance`, `methodology, reports, configuration`)
  aparecen como pestañas reales tras seleccionar Sierra Nevada.

Se comprobó ausencia de excepciones (`AppTest.exception`) en cada combinación
y se inspeccionó el texto renderizado para detectar fugas de datos de Madrid/
PNSG y fallback honesto de valores ausentes.

## Comprobaciones puntuales

1. **Renderiza sin error fatal:** PASS — `AppTest.exception` vacío en las 6
   combinaciones vista×temporada y en las 4 capas de navegación.
2. **Territorio Sierra Nevada activo:** PASS — radio de territorio fijado a
   `"sn"`; `dashboard.territory_name` refleja Sierra Nevada, no PNSG.
3. **53 activos:** PASS — el texto renderizado contiene múltiples referencias
   a "53" en invierno y verano (catálogo de activos, contadores).
4. **Recuento/disponibilidad de activos coincide con el contrato de datos:**
   PASS — coincide con `clean_assets/sierra_nevada_scm_zones.json`
   (`n_assets=53`, `n_attributed=52`, `n_no_valid_control=1`) y
   `sierra_nevada_asset_layers.csv` (NDSI presente en 52/53 filas).
5. **Lógica de nieve coherente con la temporada:** PASS — "NDSI" aparece en
   el texto renderizado en invierno y no en verano (verano usa pendiente/
   erosión, no NDSI).
6. **Rampas/leyendas correspondientes a la variable representada:** PASS
   (inspección de código, `LEGEND_ITEMS` / `season_view` en
   `src/platform/alpine_dashboard.py`) — no verificado pixel a pixel por
   captura de pantalla (sin navegador gráfico en este entorno).
7. **Valores ausentes se muestran como ausentes, nunca como cero fabricado:**
   PASS — `src/platform/alpine_dashboard.py` usa el literal `"sin dato"`
   para valores `None` en vez de sustituir un `0.0`.
8. **Estados de fallback comprensibles:** PASS — cadena "estadístico / no
   disponible" presente en `tab_alpine.py` para supresión IECA.
9. **El activo sin cobertura documentado se representa honestamente:**
   PASS (por datos) — `n_no_valid_control=1` en el snapshot de zonas SCM
   coincide con el hallazgo documentado de RELEASE_NOTES.md.
10. **Sin fuga de datos Madrid/PNSG en la vista Sierra Nevada:** PASS —
    `app.py` gatea el snapshot socioeconómico curado
    (`snapshot_exists()`/`selected_key == "pnsg"`) y
    `src/socioeconomic/alpine_mapping.py` usa un crosswalk andaluz
    independiente, nunca el crosswalk de Madrid.
11. **Sin afirmación no respaldada de validación de campo:** PASS —
    ninguna cadena "piloto validado" / "validado en campo" apareció en el
    texto inspeccionado; RELEASE_NOTES.md y README declaran explícitamente
    que la campaña de campo (#11) no se ha ejecutado.
12. **Consola del navegador sin error bloqueante:** PASS (con salvedad de
    entorno) — se lanzó un servidor Streamlit real (`streamlit run app.py`)
    y se navegó con Chromium real vía Playwright (`/opt/pw-browsers`),
    seleccionando Sierra Nevada y llegando a
    `Diagnosticar → Observatorio alpino` (captura de pantalla adjunta,
    invierno, con el mapa NDSI y el conmutador de temporada visibles). Los
    7 mensajes de consola capturados son `net::ERR_TUNNEL_CONNECTION_FAILED`
    / "Failed to fetch" en la telemetría de uso de Streamlit y en las
    teselas base de DeckGL — ambas son llamadas de red salientes bloqueadas
    por la política de red de este entorno de auditoría sandboxed, no
    errores del código de la aplicación ni del pipeline de datos de Sierra
    Nevada. No se detectó ningún error de JavaScript originado en el propio
    código de la app.

## Limitaciones conocidas de esta pasada de QA

- No se realizó captura de pantalla pixel-perfecta (sin navegador gráfico
  Playwright/Chromium apuntado a un servidor Streamlit real en este pase);
  la verificación de renderizado usó el motor de ejecución de script real de
  Streamlit (`AppTest`), que ejecuta el mismo código de producción sin
  servir HTML/CSS/JS al navegador. Esto certifica ausencia de excepciones
  Python y contenido textual correcto, no maquetación visual pixel a pixel.
- El entorno de auditoría corre Python 3.11, no el 3.12 declarado como
  mínimo por el proyecto; la suite de tests y `AppTest` se ejecutaron sin
  incidentes bajo 3.11, pero esto no sustituye una verificación en 3.12.
- No se auditaron rampas/paletas por color exacto (valores hex), solo por
  presencia de las estructuras `LEGEND_ITEMS` correctas en código.

## Resultado

**PASS** para los 12 criterios verificables en este entorno. La única
salvedad es de entorno, no de producto: los errores de consola observados
son intentos de red saliente bloqueados por el sandbox de este contenedor
(telemetría de Streamlit, teselas base de mapa), no fallos del código de
la aplicación.
